Foundation, DspCore and MCC package resolution and compatibility contract.

MIDILAR links Foundation::Foundation, DspCore::DspCore and MCC::MCC publicly. It requires Foundation 2.0.5 or a newer 2.x release (built on CPSTL 1.1.5), DspCore 0.1.1 or a newer 0.x release, and MCC 0.6.0 or a newer 0.x release. It rejects packages whose recorded platform differs from the selected MIDILAR preset.

Foundation is resolved first (cmake/MIDILARFoundation.cmake), then DspCore (cmake/MIDILARDspCore.cmake) and MCC (cmake/MIDILARMCC.cmake) with the same order: a parent-project target, MIDILAR_DSPCORE_PREFIX or MIDILAR_MCC_PREFIX, the corresponding sibling export, normal find_package, and finally the GitHub Release package or, for AVR and Arm, the sources at the pinned tag built with MIDILAR's toolchain. The Foundation steps below are mirrored by the DspCore and MCC ones.

Resolution order (cmake/MIDILARFoundation.cmake):

  1. A Foundation::Foundation target defined by a parent project.
  2. -DMIDILAR_FOUNDATION_PREFIX=<prefix> or the MIDILAR_FOUNDATION_PREFIX environment variable. An unusable explicit prefix is an error.
  3. ../Foundation/dist/<preset> for sibling repositories. An incompatible sibling export is ignored with a warning.
  4. Normal find_package(Foundation CONFIG) search rules.
  5. When MIDILAR_FETCH_FOUNDATION is ON (default):
    • the GitHub Release package Foundation-<version>-<preset> for tag v<version>, verified against its published SHA-256 file;
    • otherwise the Foundation sources at that tag, fetched with FetchContent and built with MIDILAR's toolchain. Installing MIDILAR then also installs Foundation into the same prefix.

Fetched content lives in build/<preset>/_deps/ and is reused across reconfigurations. FETCHCONTENT_SOURCE_DIR_FOUNDATION builds a local Foundation working copy instead of cloning, and -DMIDILAR_FETCH_FOUNDATION=OFF disables network access.
