Detailed Description

Byte-oriented builders, adapted from the historical Message API.

Complete messages

Message holds one complete short message in three inline bytes. Note On, Note Off, AfterTouch, CC and Pitch Bend use three MIDI bytes. Program Change and Channel Pressure use two. Real-time messages use one. The status byte determines size(), so there is no allocation or separate size field. SetRawData accepts one complete validated message, not a stream fragment.

#include <MIDILAR_Protocol.h>
using MIDILAR::Protocol::Midi::Message;
Message msg;
msg.NoteOn(60, 100, 0); // wire channel 0 = human channel 1
// Send msg.Buffer(), msg.size() using the application's MIDI transport.
auto packet = MIDILAR::Protocol::Ump::Encode(MIDILAR::Protocol::Ump::Group::FromNumber(1), msg);
auto bytesAgain = MIDILAR::Protocol::Ump::DecodeMidi1(packet);

Storage and validity

Builders mutate the object and return Message&. Invalid input clears it: IsValid() is false, Buffer() is null and size() is zero. Data(index) returns zero outside size(). A copy owns its three independent bytes.

SysExMessage is different: it is a non-owning view of a caller buffer. Copies alias the buffer. Keep it alive and unchanged for the entire view's use. Build takes payload without F0/F7, validates all bytes and capacity, and writes nothing on failure. There is no hidden allocation or truncation.

uint8_t storage[16];
const uint8_t payload[] = {0x7D, 1, 2, 3};
auto sysex = MIDILAR::Protocol::Midi::SysExMessage::Build(
storage, sizeof(storage), payload, sizeof(payload));
// sysex.Buffer(): F0 7D 01 02 03 F7, size(): 6.

Migration from MidiCore::Message

  • Include MIDILAR_Protocol.h and use MIDILAR::Protocol::Midi::Message.
  • NoteOn, NoteOff, AfterTouch, ControlChange, ProgramChange, ChannelPressure, common CC helpers, transport and system-common builders retain their useful names and argument order. Channels remain wire indices 0-15.
  • Invalid arguments are rejected instead of silently clamped. The current Channel wrapper still uses FromWire/FromNumber for explicit conversion.
  • PitchBend always takes 0-16383. Use PitchBendSigned for -8192..8191 and PitchBend7 for 0-127. Overload resolution no longer changes the meaning.
  • Replace dynamic SystemExclusive and MTC_FullFrame methods with SysExMessage::Build and SysExMessage::MTC_FullFrame using caller storage.
  • Vector constructors, iterators and implicit ownership are not retained.
  • The old NRPN helpers were empty. Compose CC 99/98 and Data Entry 6/38 explicitly; see NRPN Messages. One Message holds one CC.
  • Ump::Midi1Parser and the existing devices continue to use Ump::Packet. Construction and raw-byte access need no UMP conversion. Ump::Encode requires an explicit group and normalizes velocity-zero Note On; Ump::DecodeMidi1 accepts short MIDI 1.0 UMP only, discards its group and never downconverts MIDI 2.0.
  • This is an adapted API, not binary or source compatibility with the removed implementation. See SPEC-M1-1..4 in MIDI-Domain Specification.
